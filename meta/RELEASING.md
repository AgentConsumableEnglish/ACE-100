# Releasing ACE-100

This file is development-side truth. Nothing under `meta/` is governed by the
standard (see `.ace-ignore` at the root). Two release assets are *built from*
`meta/`, though: `adopt.sh` is uploaded as-is, and the skill tarball is built
from `meta/skill/` (with `--migrate`, its SKILL.md lands in adopter repos).

## What the repository is

The repository root **is** the kit: `README.md`, `docs/`, `tools/`. Everything
an adopter receives comes from those three paths. `meta/` holds what must not
ship: this file, the publish and adopt tooling, the ace-migrate skill source,
and the field reports that drive issues (`meta/reports/`).

## The issue cycle

- The release driver is field reports from real adopters (the indavi monorepo
  so far, ~1,800 governed docs). Reports land in `meta/reports/`.
- Each report is read and its suggestions are folded into the standard as a
  new issue — adopted wholesale, then dogfooded on the kit itself. The kit
  must pass its own checkers at every commit.
- Issue control (docs/standard/about.md): a change to a **rule** makes a new
  issue, a dictionary change does not. Checker-only changes have also shipped
  without a new issue (that practice is ours; about.md states only the rule
  and dictionary clauses).
- Every change lands in docs/standard/changes.md, and the agent brief and
  checklist are updated in the same pass.
- Other sources (e.g. the caveman review in Issue 3) are sanctioned but must
  be attributed by name in about.md Sources and in changes.md.

## Releasing an issue

Before the release commit:

1. Fold everything into `## Issue N — draft` in docs/standard/changes.md as
   you go. At release, retitle it `## Issue N — YYYY-MM-DD`.
2. Remove every "draft" wording from the kit files — prose *and* the tool
   headers ("Issue N draft" in check.sh, lint.py, measure.py). Known spots:
   README.md, about.md, changes.md, docs/standard/README.md's description,
   tools/README.md. The gate greps all kit paths, inflections included:
   `grep -rniE draft README.md docs tools` must come back empty.
3. Run `python3 tools/measure.py` and commit the snapshot as
   `tools/measurements/issue-N.txt`. The standard makes no quantitative claim
   without it.
4. Make sure main is pushed and clean.

Then:

    meta/publish.sh issue-N --dry-run   # gates + build only, inspect meta/dist/
    meta/publish.sh issue-N             # tags, pushes, creates the GitHub Release

The full gate list: on main; clean worktree; origin points at the canonical
repository; main == origin/main; tag absent (unless resumable, below); both
checkers sweep clean; no "draft" inflection anywhere in kit files; dated
changes.md heading; measurement snapshot present; adopt.sh parses under
`bash -n` and `sh -n`; the skill's SKILL.md exists; gh authenticated (real
runs only).

### If a publish fails half-way

`gh release create` can fail after the tag is pushed (upload timeout, expired
token). A re-run detects the resumable state — same tag, pointing at HEAD, no
release — and publishes without re-tagging. If the tag landed on the *wrong*
commit, delete it remotely first (`git push origin :refs/tags/issue-N`), then
locally (`git tag -d issue-N`), then rerun; a plain `git fetch` re-follows
remote tags, so the remote deletion must come first.

## Release artifacts

| Asset | Name | Note |
|---|---|---|
| Kit tarball | `ace-100-kit-issue-N.tar.gz` | `README.md docs/ tools/` + generated `tools/kit-manifest.txt` |
| Skill tarball | `ace-100-skill-issue-N.tar.gz` | `ace-migrate/SKILL.md` from `meta/skill/` |
| Adopt script | `adopt.sh` | **stable name** — the evergreen entry point |

The one-liner depends on the stable name:

    curl -fsSL https://github.com/AgentConsumableEnglish/ACE-100/releases/latest/download/adopt.sh | sh

adopt.sh resolves the newest issue from the `releases/latest` redirect and
then downloads the *versioned* tarball, so everything except the entry point
carries its issue number. Renaming `adopt.sh` breaks every published
one-liner — do not.

## The manifest

`tools/kit-manifest.txt` is generated by publish.sh into the tarball (it is
not a committed file). Format: header line carries the issue tag, two legend
comment lines follow it, then one `<class> <path>` line per file. adopt.sh
validates every path — old manifest and new alike — against a containment
rule (under `docs/` or `tools/`, no absolute form, no `..`), so a manifest
line can never write or delete outside those two trees.

- `kit` — the standard's own files. adopt.sh overwrites them on upgrade and
  deletes ones a newer issue dropped (old-vs-new manifest diff).
- `seed` — files the adopter extends. Copied once, never touched again:
  `docs/README.md`, `docs/dictionary/technical-terms.md`,
  `docs/standard/deviations.md`. The seed list lives in publish.sh — keep it
  in sync with any new adopter-extended file the standard grows.

The kit's root `README.md` ships in the tarball but is deliberately absent
from the manifest: it never lands in an adopter repo. Adopters keep their own
root README — adopt.sh appends a link to docs/README.md when one is missing,
and creates a minimal conforming root README only when none exists at all.

## The ace-migrate skill

Source: `meta/skill/ace-migrate/SKILL.md`. Installed by `adopt.sh --migrate`
into the vendor-neutral `.agents/skills/` directory (the skills-ecosystem
convention). Cursor, Codex, Copilot, OpenCode, Cline, Amp, and Zed read that
directory natively; Claude Code, Windsurf, and Continue get a relative
symlink (`.claude/skills/ace-migrate -> ../../.agents/skills/ace-migrate`)
when their directory exists in the target repo.

## Testing without a release

Both fetches have local overrides, so the whole adopt flow is testable before
any GitHub Release exists:

    meta/publish.sh issue-N --dry-run       # build meta/dist/ artifacts
    # in a scratch clone whose origin is a local path, also set:
    #   ACE_PUBLISH_REPO_SLUG=<something the origin URL contains>
    cd "$(mktemp -d)" && git init -q .
    ACE_ADOPT_KIT_TARBALL=/path/to/ace-100/meta/dist/ace-100-kit-issue-N.tar.gz \
    ACE_ADOPT_SKILL_TARBALL=/path/to/ace-100/meta/dist/ace-100-skill-issue-N.tar.gz \
    sh /path/to/ace-100/meta/adopt.sh --migrate

Scenarios worth re-testing after adopt.sh changes: fresh adopt, re-run
(idempotent upgrade), legacy upgrade (kit present, no manifest), conflict
abort (non-ACE docs/ present), pinned issue argument, --owners, --migrate
symlinks, and a non-git directory.

## Writing prose in this repository

Kit prose must pass both checkers (`tools/check.sh`, `python3 tools/lint.py`
— run them after any prose edit). Two traps specific to shipped files:

- Never backtick a `meta/` or `.agents/` path in a shipped document: ACE 14.9
  resolves backticked paths, and those directories do not exist in adopter
  repos (or in this repo, for `.agents/`). Fenced code blocks are exempt.
- The word "draft" is fine during a draft but blocks the publish gate — keep
  it only in the places the release step rewrites (README.md, about.md,
  changes.md).
